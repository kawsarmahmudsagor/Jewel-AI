## COORDINATE SYSTEM — measurement convention
════════════════════════════════════════════════════════
You are measuring a vertical "assembly stack": how far each component sits ABOVE the top
surface of the band, looking at the ring head-on (the band is a vertical circle, the stone
perched on top). These are RELATIVE heights, not world coordinates — the code generator will
anchor them onto the band's outer surface, so you only need them consistent with each other.

- The reference plane is the TOP of the band (the seat the head rests on): call this height 0.
- Component heights (gallery top, stone girdle, table, prong tip) are POSITIVE distances measured
  UPWARD from that band-top reference, in mm.
- "Band thickness" is a RADIAL dimension (how deep the metal is, inner wall → outer surface).
  Do NOT confuse it with any Z/height value — they are different quantities.
- The finger hole is the open circle of the band; it has no separate "bottom plane."
- All linear measurements in millimeters (mm). All angles in degrees.

════════════════════════════════════════════════════════
Assume US size 6 (inner diameter ≈ 16.5 mm) unless evidence suggests otherwise.
US size 7 = 17.3 mm. US size 8 = 18.2 mm.
Use the band-width-to-inner-diameter ratio visible in the image to calibrate all other measurements.

## STEP 3 — ASSEMBLY STACK Z-MAP (extract before filling schema)
════════════════════════════════════════════════════════
These heights are the vertical skeleton of the model — RELATIVE distances above the band-top
reference (height 0). Extract them first and keep them consistent with each other.

- bandTopZ    : always 0 (the band-top reference plane; the seat for the head)
- bandBottomZ : leave 0 unless a feature clearly sits below the band top (e.g. a peg/under-bezel).
                This is NOT the band's radial thickness — record thickness in section 2 instead.
- galleryBaseZ: where the basket/head foot begins relative to band top, typically 0
- galleryTopZ : height above band top where gallery walls end and the stone sits (e.g. 4.5)
- stoneGirdleZ: equals galleryTopZ for prong/basket settings; may differ for bezel
- stoneTableZ : stoneGirdleZ + crown height (crown height ≈ stone_diameter × 0.16 for round brilliants)
- prongTipZ   : stoneTableZ + extensionAboveStone. MEASURE extensionAboveStone directly from the
                gap you can see between the prong tips and the table in the image — do not default
                to a typical value. Most well-set prongs end AT or barely above the table (0–0.6 mm);
                only use anything near 1.0–1.5 mm if the photo clearly shows tall talon-style prongs
                rising well past the crown. If the prongs are not visible/obscured, use 0.4 mm.
- haloPlaneZ  : set 0 if no halo; otherwise ≈ galleryBaseZ

## STEP 4 — STONE CUT PROPORTIONS (use as estimation defaults)
════════════════════════════════════════════════════════
When stone depth cannot be directly measured, use these industry-standard proportions:

Round brilliant : table 56%, crownAngle 34.5°, pavilionAngle 40.8°, crownHeight 16%, pavilionDepth 43%, girdle 3%, facets 58
Princess        : table 75%, crownAngle 14°,   pavilionAngle 40°,   crownHeight 14%, pavilionDepth 75%, L/W ratio 1.0
Oval            : brilliant proportions, L/W ratio 1.35–1.5
Emerald (step)  : table 62%, crownAngle 13°,   pavilionAngle 48°,   L/W ratio 1.4
Cushion (mixed) : table 60%, crownAngle 35°,   pavilionAngle 43°,   L/W ratio 1.05–1.1
Marquise        : brilliant proportions, L/W ratio 1.85–2.1
Pear            : brilliant proportions, L/W ratio 1.45–1.75
Cabochon        : dome only, no facets, pavilionDepth ≈ 50% of diameter

## STEP 6 — FILL SCHEMA SECTIONS 1–8
════════════════════════════════════════════════════════

General rules:
1. Populate ALL fields. Use null ONLY when a field is genuinely indeterminate from the image.
2. For fields with "options" arrays: choose exactly one listed option — never invent new values.
3. Use assemblyStack Z values as anchors for all vertical positions in the schema.
4. Count prongs carefully — look at highlights, shadows, and reflection symmetry.
5. For repeated elements (prongs, pavé stones): include one entry per detected instance (up to 20 for pavé).
6. Set confidenceScore 0.0–1.0 for each component.

### Prong geometry — fill into section 5 (centerStoneAnalysis.setting):
- prongAngularPositions: e.g. [0, 90, 180, 270] for 4-prong; [0, 60, 120, 180, 240, 300] for 6-prong
- baseRadialOffset: mm from ring center where prong starts (≈ stone_radius + 0.2 mm)
- tipRadialOffset: mm at prong tip — a real prong CURLS INWARD to grip the crown facet edge, so the
  tip sits INSIDE the table radius, not outside it. tipRadialOffset must be LESS than table_radius
  (gem_table_diameter / 2). Do not add an outward splay at the tip; any splay belongs lower, near
  the girdle, before the prong bends over the stone.
- splayAngleDegrees: outward tilt from vertical near the base only — typically 4–5°, range 0–8°
- extensionAboveStone: mm of prong visible above stone table — measure from the image, do not
  default; most prongs sit at 0–0.6 mm above the table (see STEP 3 guidance)
- extensionBelowGirdle: mm prong extends into gallery below girdle (1.5–2.0 mm typical)

### Gallery details — fill into section 7 (galleryHeadAssemblyAnalysis):
- outerDiameterAtBase, outerDiameterAtTop, innerDiameterAtBase, innerDiameterAtTop (mm)
- totalHeight (= galleryTopZ from assembly stack)
- wallThickness (mm)
- railCount: 0, 1, or 2 horizontal rails visible
- railHeight: mm (height of each rail)
- windowCount: number of openings in basket walls
- windowShape: arch | rectangular | oval | none
- If cathedral style: riseHeight (mm), profileCurve shape

### Band cross-section — fill into section 2 (ringBandAnalysis.bandGeometry):
- crossSectionalShape.type: Round | Comfort Fit | Half Round | Flat | Knife Edge | Custom
- Estimate outerRadius of cross-section arc
- Estimate innerCurvatureRadius for comfort-fit inner dome (typically 15–20 mm)
